# منصة الويب ولوحة التحليلات

هذا الدليل يصف الملفات الموجودة فعلياً في المستودع. لا تحتوي لوحة الإدارة على بيانات تجريبية، ولا تعرض أرقاماً قبل اتصالها بخاصية Google Analytics 4.

## تطبيق الويب

الموقع موجود في `web/` ويستخدم Next.js App Router وReact وTypeScript وTailwind CSS. شغّله محلياً:

```powershell
Set-Location "C:\Users\hassa\Desktop\all project\iptv app\web"
npm install
npm run dev
```

يعمل محلياً على `http://localhost:3000`. إعداد Firebase Web موجود كقالب في `.env.example`. بعد تسجيل تطبيق Web في مشروع Firebase، انسخ الإعدادات العامة إلى ملف `web/.env.local`، ثم أعد تشغيل Next.js. قيم Firebase Web identifiers عامة وليست اعتماد حساب خدمة.

أحداث الويب المسجلة: `content_open` و`search` و`playback_start` و`playback_error`. يرسل حدث البحث فئة طول تقريبية فقط، ولا يرسل النص المكتوب. يبدأ قياس الويب بعد توفير إعداد التطبيق وإعادة تشغيل الموقع.

## لوحة تحليلات GA4

المجلد `dashboard/` يحتوي لوحة عربية فاتحة وخادم Node.js يستخدم مكتبة Google Analytics Data API الرسمية. يبدأ الخادم محلياً فقط على `127.0.0.1:4040`:

يتطلب الخادم Node.js 22 أو أحدث.

```powershell
Set-Location "C:\Users\hassa\Desktop\all project\iptv app\dashboard"
npm install
Copy-Item .env.example .env
npm start
```

اضبط `GA_PROPERTY_ID` في `dashboard/.env`. يحتاج الخادم أيضاً إلى Application Default Credentials بصلاحية `analytics.readonly`، وإلى منح حساب الخدمة دور Viewer على خاصية GA4. يمكن تمرير المسار إلى ملف حساب الخدمة عبر `GOOGLE_APPLICATION_CREDENTIALS` أو إعداد ADC على الجهاز. احفظ ملف الاعتماد خارج المشروع؛ قواعد Git تتجاهل ملفات الحسابات الخدمية وملفات البيئة المحلية.

الأرقام التي يمكن للوحة عرضها تشمل المستخدمين النشطين في الوقت الحقيقي (آخر 30 دقيقة)، المستخدمين النشطين والجلسات و`first_open` وعدد الأحداث وعمليات البحث وفتح تفاصيل المحتوى وبدايات المشاهدة وأخطاء التشغيل، مع تجميع حسب التاريخ والمنصة والجهاز والدولة. لوحة GA4 وData API تعرض بيانات مجمّعة وقد تتأخر؛ ليست قائمة بأشخاص أو جلسات فردية.

`first_open` ليس عدد تنزيلات المتجر. تنزيلات Google Play يجب قياسها من Play Console. كما أن تقرير «أكثر الأعمال مشاهدة» يتطلب تسجيل `content_title` كبُعد مخصص بنطاق الحدث في GA4؛ إلى أن يكتمل ذلك توضح اللوحة أن هذا التقرير غير مهيأ. نصوص البحث غير مجمعة أو معروضة.

لا تنشر خادم لوحة الإدارة على الإنترنت بصورته الحالية. إذا احتجت وصولاً بعيداً، استخدم استضافة محمية بمصادقة للمشرفين وتخزين اعتماد آمن، ولا تفتح خدمة محلية بدون تحكم وصول.

## إعداد Firebase وتسجيل التطبيقات

المشروع المسجل في Firebase هو `madartv`، وحزمة Android هي `com.madar.tv`. أكمل من Firebase Console:

1. نزّل `google-services.json` للتطبيق المسجل وضعه في `MadarTV/app/`.
2. أضف تطبيق Web إلى المشروع، وانقل إعداداته إلى `web/.env.local` حسب القالب.
3. اضبط رقم خاصية GA4 واعتماد القراءة للوحة الإدارة.
4. أنشئ بُعداً مخصصاً باسم `content_title` ونطاق Event لتمكين تقرير الأعمال الأكثر مشاهدة.
5. أعد بناء التطبيق بعد إضافة ملف Android config. من دون الملف يظل البناء ممكناً لكن Firebase Analytics غير مهيأ في APK.

## بناء Android

من مجلد `MadarTV`:

```powershell
Set-Location "C:\Users\hassa\Desktop\all project\iptv app\MadarTV"
.\gradlew.bat :app:assembleDebug
```

يستخدم Release إعداد R8 للتصغير والتشويش، ولا يجعل محتوى APK مستحيلاً على التحليل. يتطلب إصدار Release مفاتيح التوقيع من متغيرات البيئة الموضحة في [توثيق حماية APK](./03_SECURITY_OBFUSCATION_V6.md). لا تحفظ ملف التوقيع أو أسراره في Git.

## مصدر البيانات وحالة التنفيذ

إنشاء مشروع Firebase وتسجيل تطبيق Android لا يعني أن القياس بدأ بالفعل. تنزيل إعداد التطبيق، تسجيل تطبيق الويب، منح Data API الوصول، ثم تشغيل نسخ محدثة من التطبيق والموقع خطوات لازمة. لا تعرض اللوحة أرقاماً مخترعة عند غياب أي خطوة منها.
