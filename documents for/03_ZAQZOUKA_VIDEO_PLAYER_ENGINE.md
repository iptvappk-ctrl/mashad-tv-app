## 1. هندسة المشغل المزدوج (Dual Player Architecture)
لتقديم أفضل تجربة مشاهدة ممكنة على كل بيئة، تم تقسيم محرك الفيديو إلى مكونين رئيسيين:
1. **مشغل الأندرويد الأصلي (Native ExoPlayer):**
   - مكتوب بلغة **Kotlin** ومعتمد على أحدث إصدارات **Media3 / ExoPlayer**.
   - يوفر فك تشفير عتادي فائق (Hardware Decoding) يدعم تنسيقات H.264 (AVC) و H.265 (HEVC) و VP9 و AV1 دون تسخين المعالج أو استنزاف بطارية الهاتف أو موارد التي في بوكس.
2. **مشغل الويب المتطور (Web HLS Player):**
   - مبني بلغة TypeScript باستخدام محرك **HLS.js**.
   - يدعم البث التكيفي (Adaptive Bitrate Streaming - ABR) وضبط جودة العرض بحسب سرعة اتصال المستخدم لحظة بلحظة.

```
       [ Zaqzouka Player Dispatcher ]
                     │
       ┌─────────────┴─────────────┐
       ▼                           ▼
[ Android ExoPlayer ]      [ Web HLS.js Player ]
(Hardware Decoded,        (Adaptive Bitrate ABR,
 D-Pad Remote Focus)       Custom Controls UI)
       │                           │
       └─────────────┬─────────────┘
                     ▼
       [ Stream Resolver Engine ]
 (Voe | Vidmoly | Vidara | Upstream)
                     │
       ┌─────────────┴─────────────┐
       ▼                           ▼
[ VAST/VMAP Ad Pre-Roll ]  [ Auto-Failover Watchdog ]
(15s Video Monetization)   (403/404 Instant Switch)
```

## 2. مشغل الأندرويد الأصلي (Android Kotlin ExoPlayer Engine)
الملف: `MadarFlutter/android/app/src/main/kotlin/...` وحزمة `zaqzouka-player-1.1.19`

### المكونات البرمجية الأساسية:
- **ExoPlayer Instance:**
  يتم إنشاء المشغل مع إعدادات تخزين مؤقت مخصصة (Custom LoadControl) تضمن بدء التشغيل السريع (Fast-Start) خلال أقل من 800 ميلي ثانية:
  - الحد الأدنى للتخزين المؤقت قبل البدء: 1.5 ثانية فقط.
  - الحد الأقصى للتخزين المؤقت: 30 ثانية لتجنب استهلاك الذاكرة العشوائية.
- **إدارة الترويسات (Custom HttpDataSource.Factory):**
  يتم حقن ترويسات أمان مخصصة لكل طلب شبكي:
  ```kotlin
  val dataSourceFactory = DefaultHttpDataSource.Factory()
      .setUserAgent("Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36")
      .setDefaultRequestProperties(mapOf(
          "Referer" to currentServerReferer,
          "Origin" to currentServerOrigin,
          "Accept" to "*/*"
      ))
      .setConnectTimeoutMs(8000)
      .setReadTimeoutMs(15000)
      .setAllowCrossProtocolRedirects(true)
  ```

## 3. محركات فك التشفير واستخراج البث (Stream Resolvers & Deobfuscators)
تعتمد مواقع الرفع على تقنيات تشفير لحماية روابط الفيديو وإجبار المستخدم على مشاهدة إعلانات منبثقة مزعجة. يقوم محرك `Zaqzouka Resolvers` بتخطي هذه الحمايات واستخراج رابط البث النظيف مباشرة:

### 1. سيرفر VOE (`voe.sx` / `delivery-node`):
- **طريقة التشفير:** تشفير الروابط بـ Base64 وعكس السلاسل النصية وحقنها داخل سكريبت مشفر بالـ Packer.
- **آلية الفك:**
  1. سحب كود HTML لصفحة الـ Embed.
  2. البحث عن نمط `let sources = { ... }` أو تفكيك السلاسل النصية المشفرة عبر Regex.
  3. استخراج الرابط المباشر لملف الـ HLS الرئيسي (`master.m3u8`) أو ملف MP4 عالي الجودة.

### 2. سيرفر Vidmoly (`vidmoly.me` / `vidmoly.net`):
- **طريقة التشفير:** استخدام `eval(function(p,a,c,k,e,d)...)` لحجب روابط المشغل.
- **آلية الفك:**
  1. تمرير كود الـ JavaScript إلى دالة فك التشفير (Unpacker Engine).
  2. استخراج الـ Array الذي يحتوي على معلمات الـ Playlist.
  3. استخراج رابط البث بصيغة `https://.../v.mp4` أو رابط الـ HLS السريع.

### 3. سيرفرات Vidara و Vidsharing و Upstream:
- فك تشفير وسوم `<source src="..." type="application/x-mpegURL">` وتمرير معلمات الـ Token المؤقتة لضمان صلاحية الرابط دون انقطاع.

## 4. آلية التبديل التلقائي بين السيرفرات عند التعطل (Automatic Server Failover)
تعتبر هذه الميزة من أقوى الركائز في استقرار التطبيق؛ حيث تضمن استمرار المشاهدة حتى في حال تعرض السيرفر الأصلي للحظر أو التوقف المفاجئ:

### استراتيجية شلال السيرفرات (Waterfall Strategy):
يتم ترتيب السيرفرات حسب السرعة والاستقرار:
1. **السيرفر الأساسي (Priority 1 - Voe):** أسرع سيرفر وأعلى دقة.
2. **السيرفر الاحتياطي الأول (Priority 2 - Vidmoly):** مستقر جداً وخوادم متعددة.
3. **السيرفر الاحتياطي الثاني (Priority 3 - Vidara / Vidsharing):** بديل قوي.
4. **السيرفر الاحتياطي الثالث (Priority 4 - Upstream / Direct CDN).**

### خوارزمية التبديل اللحظي (Auto-Switch Algorithm):
```
[ بدء تشغيل السيرفر 1 ]
         │
         ├──► تم التشغيل بنجاح؟ ───► [ استمرار العرض دون انقطاع ]
         │
         └──► خطأ؟ (403 Forbidden / 404 Not Found / Timeout > 5s)
                   │
                   ▼
       [ إرسال تنبيه في لوحة الأدمن ]
                   │
                   ▼
       [ حفظ ثانية التوقف الحالية ]
                   │
                   ▼
       [ الانتقال فوراً إلى السيرفر 2 ]
                   │
                   ▼
       [ استئناف البث من نفس الثانية بدقة ]
```

## 5. محرك إعلانات الفيديو الرقمية (VAST / VMAP 15s Pre-Roll Ads Engine)
تم تجهيز مشغل الفيديو لدمج إعلانات الفيديو الرقمية المتوافقة مع معايير **IAB (Interactive Advertising Bureau)** لتحقيق أقصى ربحية ممكنة كما تفعل كبرى المنصات:

### آلية عمل إعلان الـ Pre-Roll:
1. **طلب الإعلان (Ad Request):**
   - قبل بدء دفق الفيلم أو المباراة، يرسل المشغل طلب VAST XML إلى شبكة الإعلانات المتعاقد معها (مثل Google AdManager أو AppLovin أو Prebid).
2. **عرض فيديو الإعلان (15 ثانية):**
   - تشغيل إعلان فيديو عالي الجودة مدته 15 ثانية غير قابل للتخطي.
   - إظهار عداد تنازلي أنيق في الزاوية: `سيبدأ المحتوى خلال 15 ثانية...`.
3. **صمام الأمان لعدم إزعاج المستخدم (Zero-Churn Fallback):**
   - إذا استغرقت شبكة الإعلانات أكثر من 2.5 ثانية للرد، أو حدث خطأ في تحميل الإعلان (No Ad Fill / Network Timeout)، يتخطى المشغل خطوة الإعلان فوراً ويبدأ تشغيل الفيلم مباشرة دون أن يشعر المستخدم بأي تأخير!

## 6. التحكم عبر الريموت وأجهزة التلفزيون (TV Remote Controls & Gestures)
تم تزويد المشغل ببرمجة شاملة لأوامر أجهزة التحكم عن بعد (Key Events Handling):

| زر الريموت | الوظيفة في المشغل |
|---|---|
| **D-Pad Center (OK)** | إيقاف مؤقت / استئناف التشغيل (Play / Pause) وإظهار شريط التحكم |
| **D-Pad Right (يمين)** | تقديم سريع 10 ثوانٍ (Seek +10s) مع إظهار شاشة معاينة مصغرة |
| **D-Pad Left (يسار)** | ترجيع 10 ثوانٍ (Seek -10s) |
| **D-Pad Up (فوق)** | إظهار قائمة اختيار السيرفرات وقائمة تبديل الحلقات |
| **D-Pad Down (تحت)** | إظهار إعدادات الجودة ومسارات الصوت والترجمة |
| **Back Button (رجوع)** | ضغطة أولى لإخفاء القوائم، ضغطة ثانية للخروج وتحديث موضع المشاهدة |

## 7. معالجة الأخطاء وحيل تخطي الحظر (Anti-Hotlinking & Error Resilience)
1. **تخطي حظر الـ Referer والـ Origin:**
   - بعض سيرفرات الفيديو تفحص مصدر الطلب؛ في حال كان الطلب قادماً من تطبيق غريب يتم حظره بكود `403 Forbidden`.
   - يقوم المشغل بتزييف الـ Referer الأصلي لموقع الرفع (Header Spoofing) ليبدو الطلب وكأنه صادر من متصفح نظامي داخل صفحة المزود نفسه.
2. **التعامل مع ملفات m3u8 ذات الروابط النسبية (Relative URI Rewriting):**
   - يقوم المشغل بإعادة كتابة روابط أجزاء الفيديو (`.ts segments`) النسبية لربطها بعنوان السيرفر الأساسي لمنع فشل تحميل الشرائح.
3. **كاش الروابط المؤقتة (Session Stream Caching):**
   - تخزين الروابط المباشرة المستخرجة لمدة 4 ساعات لمنع تكرار استدعاء محركات السحب مع كل عملية إيقاف وتشغيل، مما يوفر سرعة استجابة مذهلة.
