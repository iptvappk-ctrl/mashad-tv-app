## 1. المبدأ الهندسي: كيف تضمن السيطرة 100% حتى لو شاركت الكود؟
في عالم البرمجيات والتطبيقات الكبرى، **الكود المصدري المكتوب ليس هو مصدر القوة الحقيقي، بل السحابة المركزية ومفاتيح التحكم (Cloud Infrastructure & Master Keys)**.

حتى لو أعطيت شريكك مجلد المشروع كاملاً بكل أسطر الكود ليرفعه أو يراجعه:
- تطبيق الهاتف (`MadarFlutter`) وبوابة الموقع (`Web`) مرتبطان مباشرة بسيرفرك السحابي على **Vercel** وقاعدة بيانات **Firebase**.
- في كل مرة يُفتح فيها التطبيق أو الموقع، يتم فحص إذن التشغيل من بوابتك السحابية (`/api/admin/license-check`).
- أنت فقط من يملك حساب Vercel الأصلي وحساب Firebase، وبالتالي **أنت فقط صاحب زر التشغيل والإيقاف (Kill Switch)**.

## 2. الطبقات الثلاث لحماية المالك (3-Layer Security Architecture)

```
                     ┌───────────────────────────────────┐
                     │          جهاز المستخدم            │
                     │    (تطبيق زقزوقة أو الموقع)       │
                     └─────────────────┬─────────────────┘
                                       │
                      1. طلب الإذن عند فتح التطبيق
                      POST /api/admin/license-check
                      x-zaqzouka-key: [مفتاحك السري]
                                       ▼
                     ┌───────────────────────────────────┐
                     │    سيرفرك السحابي على Vercel      │
                     │ (dashboard-api.vercel.app)        │
                     └─────────────────┬─────────────────┘
                                       │
                ┌──────────────────────┴──────────────────────┐
                ▼                                             ▼
      [ فحص الـ Kill Switch ]                     [ فحص مفتاح الـ API ]
      هل المالك أصدر أمر إيقاف؟                    هل النسخة تحمل تصريحاً؟
                │                                             │
      ┌─────────┴─────────┐                         ┌─────────┴─────────┐
      │                   │                         │                   │
  ✅ لا (طبيعي)       ❌ نعم (مُعطّل)            ✅ مطابق            ❌ غير مطابق
      │                   │                         │                   │
      ▼                   ▼                         ▼                   ▼
[ يفتح التطبيق فوراً ]  [ شاشة حمراء مقفولة 🔒 ] [ تشغيل كامل ]      [ إيقاف النسخة فوراً ]
```

### الطبقة الأولى: قفل الطوارئ اللحظي (Global Cloud Kill Switch):
- بمجرد إرسال أمر واحد من هاتفك، يتم قفل التطبيق والموقع في كل العالم خلال **أقل من ثانية واحدة**.
- تظهر للمستخدم شاشة سوداء/حمراء مع قفل 🔒 ورسالة صيانة رسمية لا يمكن تخطيها.

### الطبقة الثانية: مفتاح الحماية السري (API Key Guard):
- التطبيق والموقع يحملان ترويسة سرية (`x-zaqzouka-key`).
- لو قام الشريك بأخذ الكود ومحاولة تعديله أو تشغيله دون موافقتك، يكفي أن تغيّر قيمة `ZAQZOUKA_API_KEY` في لوحة Vercel الخاصة بك، فتتوقف كل نسخه المنسوخة فوراً.

### الطبقة الثالثة: ملكية البيانات التاريخية (Data & Firebase Monopoly):
- قاعدة بيانات المشاهدين والجلسات وسوق الإعلانات مخزنة في حساب Firebase الخاص بك حصراً.
- أي نسخة يحاول تشغيلها بعيداً عنك ستبدأ **من الصفر تماماً بلا أي بيانات وبلا أي سجلات وبلا ربط مع المشترين**.

## 3. دليل استخدام قفل الطوارئ (Kill Switch Quick Commands)
يمكنك تنفيذ هذه الأوامر من أي حاسوب أو حتى من متصفح هاتفك المحمول أو عبر تطبيق Postman:

### 🛑 1. إيقاف التطبيق والموقع بالكامل فوراً:
```bash
curl -X POST https://zaqzouka-dashboard-api.vercel.app/api/admin?route=kill-switch \
  -H "Content-Type: application/json" \
  -H "x-master-secret: YOUR_MASTER_SECRET_HERE" \
  -d '{
    "action": "kill",
    "target": "all",
    "message": "عذراً، تطبيق زقزوقة متوقف حالياً لأعمال الصيانة والتطوير الدورية.",
    "messageEn": "Zaqzouka TV is temporarily offline for scheduled system upgrades."
  }'
```

### 🛑 2. إيقاف الموقع فقط (وإبقاء التطبيق):
```bash
curl -X POST https://zaqzouka-dashboard-api.vercel.app/api/admin?route=kill-switch \
  -H "Content-Type: application/json" \
  -H "x-master-secret: YOUR_MASTER_SECRET_HERE" \
  -d '{
    "action": "kill",
    "target": "web",
    "message": "بوابة الويب تحت الصيانة، يرجى استخدام تطبيق الهاتف."
  }'
```

### ✅ 3. إعادة تشغيل المنظومة وفك القفل:
```bash
curl -X POST https://zaqzouka-dashboard-api.vercel.app/api/admin?route=kill-switch \
  -H "Content-Type: application/json" \
  -H "x-master-secret: YOUR_MASTER_SECRET_HERE" \
  -d '{"action": "restore"}'
```

### ℹ️ 4. فحص حالة المنظومة (هل هي معطلة أم تعمل؟):
```bash
curl -X GET https://zaqzouka-dashboard-api.vercel.app/api/admin?route=kill-switch \
  -H "x-master-secret: YOUR_MASTER_SECRET_HERE"
```

## 4. مفتاح ترخيص التطبيق والموقع (API Key Guard & Build Lockdown)
في لوحة تحكم **Vercel**:
1. اذهب إلى: **Project Settings** -> **Environment Variables**.
2. المفاتيح السرية الخاصة بك:
   - `MASTER_SECRET`: كلمة السر القصوى التي تفعل بها الـ Kill Switch (لا تعطيها لأي مخلوق).
   - `ZAQZOUKA_API_KEY`: مفتاح ترخيص النسخ المصرح بها (القيمة الافتراضية: `ZQ-OWNER-2026-SECRET-14MOON`).
3. إذا أردت إبطال كل النسخ التي بحوزة شريكك دفعة واحدة:
   - غيّر قيمة `ZAQZOUKA_API_KEY` في Vercel إلى أي نص عشوائي جديد.
   - فوراً، أي تطبيق أو موقع يستخدم المفتاح القديم سيفشل في اختبار الترخيص ويظهر شاشة: *"تطبيق غير مصرح به"*.

## 5. ماذا تملك أنت مقابل ماذا يملك شريكك؟ (Ownership Matrix)

| العنصر البرمجي أو الخدمي | شريكك | أنت (المالك) | ملاحظات الأمان |
|---|:---:|:---:|---|
| **ملفات الكود المصدري (Flutter / Next.js)** | ✅ يملك نسخة | ✅ تملك الأصل | الكود مجرد واجهة؛ القوة في السحابة |
| **حساب Vercel المستضيف للـ API** | ❌ لا يملك | ✅ **أنت فقط** | لا تشارك بريدك أو كلمة مرور Vercel |
| **حساب Firebase وقاعدة البيانات** | ❌ لا يملك | ✅ **أنت فقط** | ملف `service-account.json` خاص بك |
| **سلطة تفعيل الـ Kill Switch** | ❌ مستحيل | ✅ **بنقرة زر** | يتطلب `MASTER_SECRET` السري |
| **داتا المستخدمين وسوق الإعلانات** | ❌ صفر | ✅ **مملوكة لك** | كل إحصائيات الـ 30+ ألف جلسة عندك |
| **التحكم بروابط السيرفرات والبث** | ❌ مقيد | ✅ **مطلق** | السيرفر يوزع الروابط والـ API |

## 6. السيناريوهات العملية وخطوات الرد الفوري (Emergency Playbook)

### 🔴 السيناريو الأول: حدث خلاف وأخذ شريكك الأكواد وادعى أنها ملكه:
**خطتك الفورية:**
1. افتح طرفية الأوامر أو Postman وفعل الـ **Kill Switch** فوراً.
2. كافة المستخدمين الذين قاموا بتثبيت تطبيقه أو فتح موقعه سيتوقف عندهم التطبيق تماماً وتظهر شاشة الإيقاف.
3. توجه لحساب Vercel وغيّر `ZAQZOUKA_API_KEY` و `FIREBASE_DATABASE_URL`.
4. ابدأ أنت بنشر نسختك الرسمية الخاصة بك — المستخدمون سيعودون لمن يملك البث الحي الحقيقي وليس لمن يملك كوداً معطلاً!

### 🟡 السيناريو الثاني: شريكك يحاول رفع التطبيق على Google Play باسمه:
**خطتك:**
1. مفتاح توقيع التطبيق الأصلي (`keystore` و `key.properties`) احتفظ به دائماً على فلاش ميموري خاص بك ولا تضعه على GitHub.
2. بدون الـ Keystore الأصلي، لا يمكنه تحديث التطبيق الموجود على المتجر أو تغيير حزمته.
3. وثق تاريخ الـ Commits وتاريخ الإصدار `14 moon` المرفوع باسمك وحساب GitHub الخاص بك (`iptvappk-ctrl`)، فهو حجة قانونية رقمية تثبت أسبقيتك في الملكية الفكرية وتاريخ الإنشاء.

### 🟢 الخلاصة الذهبية:
> **"البرمجيات الحديثة ليست ملفات تُسرق، بل خدمات سحابية تُدار."**  
> ما دمت أنت الوحيد الذي يملك حساب Vercel وحساب Firebase ومفتاح الـ Master Secret، فأنت المتحكم بنسبة 100% في مصير المشروع في أي ثانية من ليل أو نهار.
